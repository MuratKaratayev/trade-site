# Новый сайт на хостинге PS Cloud (Plesk)

Решение владельца от 2026-10-15: новый сайт размещаем на том же хостинге PS Cloud, а не на Vercel.
Домен, DNS и почта остаются как есть.

## Как это устроено

```
push в main ──► GitHub Actions (.github/workflows/ps-cloud.yml)
                  npm ci → tsc → npm run build → папка out/ (готовые HTML, CSS, JS, картинки, .htaccess)
                  └─► ветка ps-cloud (только файлы сайта) + архив site-ps-cloud (Actions → Artifacts)
Plesk, раздел «Git» ──► забирает ветку ps-cloud в папку site/ на хостинге ──► её отдаёт nginx/Apache
```

- **Сайт собирается в статические файлы.** Next.js с `output: 'export'`, см. `next.config.ts`.
  На хостинге нет Node.js (в Plesk есть PHP, WordPress, Laravel, Joomla), а статике Node.js не нужен.
- **Редиректы со старых адресов MODX, https, «без www» и заголовки безопасности** — в `public/.htaccess`.
  Файл попадает в корень сборки. Нужен Apache: в Plesk это стандартная схема «nginx + Apache».
- **Формы заявки нет** (решение клиента 2026-10-20): на сайте только контакты. PHP новому сайту не нужен.
- **Два языка:** русский по прежним адресам, казахский — `/kk/…` (готовые файлы в `kk/` и `kk.html`; правила `.htaccess` те же).
- **Почта и DNS не трогаются**: сайт остаётся на том же сервере `195.210.46.34`.

Проверено 2026-10-15 локально на Apache 2.4 с этим `.htaccess`:
- страницы — 200, `/products/kip/` → 301 на `/products/kip`;
- все старые адреса MODX — один 301 сразу на https, `/manager/` — 404, несуществующее — 404 со страницей сайта;
- заголовки безопасности стоят, http → https и www → без www работают;
- браузерные тесты (тема, форма, якоря, логотип, фигуры, сертификаты, переполнения 320–1440), axe 0 нарушений;
- Lighthouse mobile: производительность 92–96, остальные категории 100.

## Настройка в Plesk (один раз, делает владелец)

### 0. Резервная копия старого сайта
Plesk → домен `trade-engeeniring.kz` → «Резервное копирование и восстановление» → «Создать копию».
Скачать её себе. Папку `httpdocs` со старым MODX **не удалять**: она нужна для отката.

### 1. Тестовый поддомен
1. «Сайты и домены» → «Добавить субдомен»: имя `new`, корневой каталог документов — `site`
   (полный путь получится `/site` внутри подписки, рядом с `httpdocs`).
2. У поддомена: «SSL/TLS-сертификаты» → Let's Encrypt (бесплатно).
3. Проверить, что включён Apache. «Настройки Apache и nginx» → «Режим прокси» должен быть **включён**.
   Если выключен, `.htaccess` не работает: перестанут работать редиректы и заголовки.

### 2. Git: Plesk сам забирает сборку
У поддомена `new.trade-engeeniring.kz` → «Git» → «Добавить репозиторий»:
- **Удалённый репозиторий:** `https://github.com/MuratKaratayev/trade-site.git`
  (репозиторий публичный, ключи не нужны);
- **Ветка:** `ps-cloud` (не `main`!);
- **Режим развёртывания:** автоматический;
- **Путь развёртывания:** `site` (тот же каталог, что корень поддомена).

Чтобы Plesk забирал сборку сразу после каждого обновления, нужен веб-хук.
Plesk покажет «URL веб-перехватчика» (Webhook URL). Его добавить в GitHub:
репозиторий → Settings → Webhooks → Add webhook, Payload URL — этот адрес, событие — «Just the push event».
Без веб-хука можно нажимать «Получить изменения» в Plesk вручную.

> Ветка `ps-cloud` появится после первого запуска сборки в GitHub Actions — после слияния этих изменений в `main`.
> Если ветки ещё нет: GitHub → Actions → «Build for PS Cloud» → «Run workflow».

### 3. Проверить https://new.trade-engeeniring.kz
- открываются главная, `/products/kip`, работают тема и анимации;
- `https://new.trade-engeeniring.kz/uslugi` ведёт на раздел «Услуги»;
- несуществующий адрес показывает страницу 404 сайта.

### 4. Переключить основной домен (одна настройка, мгновенный откат)
Домен `trade-engeeniring.kz` → «Хостинг и DNS» → «Настройки хостинга» → «Корневой каталог документов»:
`httpdocs` → `site`. Сохранить.

- Сайт на `trade-engeeniring.kz` сразу станет новым: те же файлы, что на `new.`.
- **Откат:** вернуть корневой каталог на `httpdocs` — старый MODX снова на месте.
- В «SSL/TLS-сертификаты» выпустить Let's Encrypt на `trade-engeeniring.kz` **и** `www.trade-engeeniring.kz`.
  Сейчас Plesk предупреждает: «Домен с префиксом www не защищён».
- Почта, DNS, IP не меняются.

### 5. После переключения
- проверить старые адреса из поиска (Яндекс/Google), например `/produkcziya/kontrolno-izmeritelnyie-priboryi/`;
- через пару недель, если всё хорошо: поддомен `new` можно удалить (папка `site` остаётся — её отдаёт основной домен);
  MODX 2.7.2 в `httpdocs` держать только как архив. Он устарел, панель MODX показывает уведомления об уязвимостях.
  Версию PHP 7.4 («устаревшая опция») новому сайту не нужна.

## Ручная загрузка (если Git в Plesk не подошёл)
GitHub → Actions → последний запуск «Build for PS Cloud» → Artifacts → `site-ps-cloud.zip`.
Plesk → «Файлы» → папка `site` → загрузить zip → «Извлечь». Файл `.htaccess` должен оказаться в корне `site`.

## Vercel
Vercel продолжает собирать превью из веток: удобно смотреть изменения до слияния.
На превью Vercel нет `.htaccess`: старые адреса и заголовки там не работают. Это нормально — боевой сайт на PS Cloud.

## Что делать до переключения домена (контент)
- Плейсхолдер «[ОТ КЛИЕНТА: …]» остался в сроках изготовления шкафов.
  «Средства автоматизации» скрыты до получения информации.
