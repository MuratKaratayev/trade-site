## Ключевые решения
- **Стек:** `next@16.3.8` (с 2026-10-14, PR #3), `react@19.3.0`, `tailwindcss@4.3.3`, `zod@4.6.5`, `typescript@5.9.3`.
  Версии закреплены точно и старше двух недель на 2026-10-13. TS 7.x (нативный порт) не брали:
  совместимость с Next 16 не проверена.
- **Тема (решение владельца, имеет приоритет над брифом «по умолчанию тёмная»):** 3 режима —
  «Как в системе» (по умолчанию), светлая, тёмная.
  - `data-theme` — фактическая тема (`light|dark`, на неё завязаны токены);
  - `data-theme-mode` — выбранный режим;
  - `localStorage.theme`: `light|dark`; нет ключа — система;
  - в SSR стоит `dark/system`, inline-скрипт исправляет до отрисовки.
- **Токены:**
  - компоненты используют только токены, `--accent` — только заливки и кнопки;
  - красный текст — `--accent-text`;
  - hover у primary-кнопки — подчёркивание: осветление красного уронило бы контраст белого ниже 4,5.
- **Моушн:** вариант A брендбука (свои SVG-компоненты). Hairline (вариант B) **не подключён** — нужно
  согласие владельца. На экране не больше одной фигуры: hero / продукция / опыт.
- **Моушн на телефоне (решение владельца, одобрено 2026-10-14):** scrub от прокрутки — `useScrollWave` считает цели
  0…1 по положению фигуры (волна идёт, пока видно ≥ `VISIBLE` = 70% фигуры; элемент на 100% ближе `PLATEAU` = 0.5 шага,
  гаснет к `REACH` = 2 шага), берёт максимум по всему пути с прошлого кадра; `useWave.scrub` сглаживает
  (подъём τ 60 мс, опускание τ 200 мс). Таймер на телефоне не годится: на обычной скорости элементы не успевают.
- **Скорость переходов (запрос владельца «помедленнее»):** якоря 0,9–1,6 с по расстоянию, появление страницы 700 мс.
  Браузерный `scroll-behavior: smooth` не используем (скорость не задать). На телефоне скорость фигур задаёт палец.
- **Десктоп-моушн:** пружина с критическим затуханием (`W = 15`) вместо перезапуска `EASE` при каждой смене цели;
  элемент под курсором — сразу и с удержанием `HOLD = 450` мс; путь курсора проверяется отрезком (`SWEEP = 3` px).
  Кольца `FALLOFF` и задержка `STAGGER` 50 мс — по брендбуку.
- **Логотип в шапке = «на главную, в самый верх»**, плавно на `/`, мгновенный старт сверху с других страниц.
- **Контраст (проверено расчётом):** все пары «текст/фон» ≥ AA. `--figure-dim` (2,2–3,1) — только для линий.
  Текст поверх фото не ставим: при затемнении .55 на светлом кадре было бы ~3,6. Подписи — под фото.
- **Логотип:** по просьбе владельца перерисован в вектор. Это отступление от правила брендбука
  «не перерисовывать» — нужно подтверждение клиента. На сайте `public/logo.svg` через `next/image` (`unoptimized`),

- **Supabase пока не подключаем** (решение владельца). Уведомления о заявках — только после согласования.

## Неудачные попытки и грабли

### Топ-грабли (удар по проду, деньгам или клиенту)
- Пока нет. Прод (`trade-engeeniring.kz`) не трогали, домен на Vercel не переключали.

### Свежие грабли
- **Функция по умолчанию в параметре хука = новая ссылка на каждый рендер.** `pick = (k) => k` в зависимостях
  `useEffect` пересоздавал эффект каждый кадр → волна «замирала» на стойке и рейке (у поля с постоянной `fieldPick` —
  нет). Значения по умолчанию для зависимостей — константы модуля (`byIndex` в `useScrollWave.ts`).
- **Быстрый курсор перепрыгивает узкие SVG-зоны:** события мыши раз в кадр, прыжок 30–60 px, `pointerenter` по
  пропущенной зоне не приходит. Тест «мелкими шагами мыши» этого не ловит — тестировать прыжками по 16 мс.
- **Отложенная цель перезаписывается в том же кадре:** подъём через очередь `next/at` терялся, если курсор ушёл до
  следующего кадра. Элемент под курсором поднимать сразу.
- **Метрики анимации обманывают:** «покой» для сравнения снимать, когда фигура за экраном (на первом экране scrub
  ставит позу сразу); headless Chrome отрисовывает примерно каждый второй кадр — прокрутка 17 px/кадр ≈ 34 px между
  отрисовками. Цифры >100% или 0% в отчёте — ошибка теста, а не сайта.
- **PR Dependabot бывает от устаревшей ветки** — его слияние откатило бы сайт. Перед слиянием `git diff --stat main <ветка>`.
- **Классификатор auto mode блокирует внешние действия** (`gh pr merge`, `gh repo edit --default-branch`, `gh pr close`)
  без явного разрешения владельца в чате. После «разрешаю …» в чате — проходит. Обходить нельзя.
- **Хук context-mode блокирует `curl`/`fetch` в Bash** — HTTP-проверки делать через `ctx_execute`.
- **HANDOFF мог быть устаревшим локально:** в начале сессии ветка отставала на 2 коммита, и в них был новый HANDOFF.
  Сначала `git fetch` + `git status -sb`, потом читать HANDOFF.
- **Раздел «Команды» был под Linux-контейнер** (`/opt/pw-browsers/...`) — на Mac владельца не работает; см. обновлённый раздел.
- Фоновая команда из цепочки тестов, заканчивающаяся `grep FAIL`, получает статус «failed» (exit 1),
  когда FAIL нет. Это не провал тестов — смотреть сам вывод.
- Свой document-обработчик клика в фазе bubble НЕ видит клики по `next/link`: Link раньше делает
  `preventDefault` и навигацию сам. Нужен `addEventListener('click', fn, true)`.
- **Не упрощать требования владельца по новому ТЗ без вопроса.** Владелец в начале просил тему «как в системе»
  по умолчанию; новый бриф сказал «по умолчанию тёмная», я сделал 2 режима — владелец недоволен. При расхождении
  ранних и новых требований — спрашивать.
- Трассировка надписи логотипа (potrace, а также скелет + перо) повторяет дрожание исходника. Чисто только
  геометрическая перерисовка по замерам. Для знака potrace подходит при сглаживании (blur 1.6 px оригинала).
  Подбор серпов эллипсами (эллипс минус эллипс) дал IoU 0,68–0,89 и потерял тонкую внутреннюю дугу — отказался.
- Разметка компонентов на сетке с шагом 2 даёт «лесенку» на краях — наращивать метки на полную сетку.
- `scroll-behavior: smooth`: в Playwright после `scrollTo` ждать или использовать `behavior:'instant'`.
- `pkill -f "next start"` в Bash убивает и сам shell (паттерн совпадает с командой) → exit 144.
  Использовать `kill $(pgrep -f "next-server|next start" | grep -v $$)`.
- В Playwright `addInitScript` выполняется при КАЖДОЙ навигации, включая reload. Не задавать через него
  `localStorage`, если проверяется сохранение. `isVisible()` считает видимым элемент за экраном.
  `colorScheme: 'no-preference'` в Chromium матчится как light.
- Первый прогон Lighthouse после `next start` «холодный» (perf 71). Мерить после прогрева, 3 прогона.
- Случайный `git rm --cached -r public/img/projects` снял фото с индекса — вернул `git add`.
  Перед коммитом смотреть `git status`.

  Версии закреплены точно и старше двух недель на 2026-10-13. TS 7.x (нативный порт) не брали:

- **Тема (решение владельца, имеет приоритет над брифом «по умолчанию тёмная»):** 3 режима —

  - `data-theme-mode` — выбранный режим;
  - `localStorage.theme`: `light|dark`; нет ключа — система;
  - в SSR стоит `dark/system`, inline-скрипт исправляет до отрисовки.
- **Токены:**

  согласие владельца. На экране не больше одной фигуры: hero / продукция / опыт.
- **Контраст (проверено расчётом):** все пары «текст/фон» ≥ AA. `--figure-dim` (2,2–3,1) — только для линий.
  Текст поверх фото не ставим: при затемнении .55 на светлом кадре было бы ~3,6. Подписи — под фото.

  Почему: корпоративный сайт почти статичный, Astro отдаёт HTML без лишнего JS, SEO из коробки.
  Моушн целиком на CSS, SVG `animateMotion` и мелком ванильном JS.
- **Тема:** атрибут `data-theme` на `<html>` (`light` | `dark`; нет атрибута = система).
  Тёмные токены в `global.css` продублированы под `@media (prefers-color-scheme: dark)`
  и под `:root[data-theme='dark']`. Это сделано намеренно, при правке менять оба блока.
