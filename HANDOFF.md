# HANDOFF — trade-site

## 🟢 СЕССИЯ 2026-10-13 (3) — сайт на Next.js по брендбуку

**Задача.** Пересобрать сайт ТОО «TRADE-Инжиниринг» (старый — https://trade-engeeniring.kz/, MODX)
по согласованному брендбуку. Стек: Next.js (App Router, TS), Tailwind v4 + CSS-токены, Vercel.
Подробное ТЗ — в сообщении владельца (в репозитории не сохранено). Ключевое ниже и в `PLAN.md`.
Решения владельца:
- переделать PR #1 (Astro удалён);
- **Supabase пока не подключать**;
- контент брать со старого сайта;
- где данных нет — видимый плейсхолдер `[ОТ КЛИЕНТА: …]`.

**Брендбук = источник правды:** `docs/brandbook/TRADE-brandbook.dc.html`. Это бандл
(gzip+base64 внутри `<script type="__bundler/manifest">`, два уровня вложенности). Распаковка:
`python3 docs/brandbook/unbundle.py <html> <папка>`, затем то же для каждого листа.
Скрипт фигур уже извлечён: `docs/brandbook/Brand-03-Motion.script.js`.

доступа (403/404) — не тратить время.

## Ключевые решения
- **Стек:** `next@16.3.7`, `react@19.3.0`, `tailwindcss@4.3.3`, `zod@4.6.5`, `typescript@5.9.3`.
  Версии закреплены точно и старше двух недель на 2026-10-13. TS 7.x (нативный порт) не брали:
  совместимость с Next 16 не проверена.
- **Тема (решение владельца, имеет приоритет над брифом «по умолчанию тёмная»):** 3 режима —
  «Как в системе» (по умолчанию), светлая, тёмная.
  - `data-theme` — фактическая тема (`light|dark`, на неё завязаны токены);
  - `data-theme-mode` — выбранный режим;
  - `localStorage.theme`: `light|dark`; нет ключа — система;
  - в SSR стоит `dark/system`, inline-скрипт исправляет до отрисовки.
- **Токены:**
  - компоненты используют только токены, `--accent` — только заливки и кнопки;
  - красный текст — `--accent-text`;
  - hover у primary-кнопки — подчёркивание: осветление красного уронило бы контраст белого ниже 4,5.
- **Моушн:** вариант A брендбука (свои SVG-компоненты). Hairline (вариант B) **не подключён** — нужно
  согласие владельца. На экране не больше одной фигуры: hero / продукция / опыт.
- **Контраст (проверено расчётом):** все пары «текст/фон» ≥ AA. `--figure-dim` (2,2–3,1) — только для линий.
  Текст поверх фото не ставим: при затемнении .55 на светлом кадре было бы ~3,6. Подписи — под фото.
- **Логотип:** по просьбе владельца перерисован в вектор. Это отступление от правила брендбука
  «не перерисовывать» — нужно подтверждение клиента. На сайте `public/logo.svg` через `next/image` (`unoptimized`),
  ширина 170 (моб.) / 218 (десктоп). Белая плашка в тёмной теме сохранена по брендбуку.
  Альтернатива без плашки — `docs/logo/logo-ondark.svg`, не подключена. Цвета знака:
  #7B6758 / #B5441E / #96351A (из медиан апскейла), текст #1B1B1F.
- **Факты** — только со старого сайта. Отрасли объектов «Угледобыча» (Шубарколь — «разрез») и
  «Химическая промышленность» (Казсода — «завод кальцинированной соды») выведены из формулировок
  старого сайта. Если клиент назовёт иначе — поправить в `content/site.ts`.

## Неудачные попытки и грабли

### Топ-грабли (удар по проду, деньгам или клиенту)
- Пока нет. Прод (`trade-engeeniring.kz`) не трогали, домен на Vercel не переключали.

### Прочее
- **Не упрощать требования владельца по новому ТЗ без вопроса.** Владелец в начале просил тему «как в системе»
  по умолчанию; новый бриф сказал «по умолчанию тёмная», я сделал 2 режима — владелец недоволен. При расхождении
  ранних и новых требований — спрашивать.
- Трассировка надписи логотипа (potrace, а также скелет + перо) повторяет дрожание исходника. Чисто только
  геометрическая перерисовка по замерам. Для знака potrace подходит при сглаживании (blur 1.6 px оригинала).
  Подбор серпов эллипсами (эллипс минус эллипс) дал IoU 0,68–0,89 и потерял тонкую внутреннюю дугу — отказался.
- Разметка компонентов на сетке с шагом 2 даёт «лесенку» на краях — наращивать метки на полную сетку.
- `scroll-behavior: smooth`: в Playwright после `scrollTo` ждать или использовать `behavior:'instant'`.
- `pkill -f "next start"` в Bash убивает и сам shell (паттерн совпадает с командой) → exit 144.
  Использовать `kill $(pgrep -f "next-server|next start" | grep -v $$)`.

## Ключевые решения
- **Формат HANDOFF:** живая часть сверху, архив снизу (только `grep -n`).
- **Стек: Astro 7 (`astro@7.3.5`, версия закреплена), чистый CSS, без UI-фреймворков и GSAP.**
  Почему: корпоративный сайт почти статичный, Astro отдаёт HTML без лишнего JS, SEO из коробки.
  Моушн целиком на CSS, SVG `animateMotion` и мелком ванильном JS.
- **Тема:** атрибут `data-theme` на `<html>` (`light` | `dark`; нет атрибута = система).
  Тёмные токены в `global.css` продублированы под `@media (prefers-color-scheme: dark)`
  и под `:root[data-theme='dark']`. Это сделано намеренно, при правке менять оба блока.
  Inline-скрипт в `<head>` ставит атрибут до отрисовки, поэтому тема не мигает.
- **Контент в `src/data/site.ts`.** Позже — Content Collections или CMS (см. `PLAN.md`, этап 4).
- **Только факты со старого сайта.** Цифры в блоке «факты» считаются из данных
  (`services.length` и т. п.), а не придуманы. Неподтверждённое (год основания, статус дилера
  TREI) на сайт не выносим, пока клиент не подтвердит.
- **Анимации:** уважаем `prefers-reduced-motion`. `[data-reveal]` прячется только при классе
  `.js`, поэтому без JS контент виден.
- **Домен с опечаткой (`engeeniring`) не меняем** без решения клиента.

### Прочее
- `[data-reveal]` нельзя вешать на элементы внутри горизонтально скроллящейся ленты:
  карточки за правым краем не пересекают viewport, и IntersectionObserver их не показывает.

  шагом ~300 px с паузой ≥250 мс или снимайте viewport.
- Шапка на 390 px: логотип + переключатель темы + бургер не помещаются, отсюда перенос темы
